B1. Current workflow – manual complaint triage

TRIGGER / INPUTComplaint arrives by email, web form, chat, social media or phone
→
HUMANLevel-1 agent opens shared inbox in arrival (FIFO) order
→
HUMANAgent reads full text, checks order history manually
→
DECISIONAgent judges category & urgency from experience (no fixed rules)
→
HUMANForwards to team by email / ticket tag; types reply from scratch
→
OUTPUTTicket assigned; customer waits for resolution
FAILURE PATHSWrong team → ticket bounced back & re-routed · Urgent safety/legal cases wait in FIFO queue · Customer chases again (repeat contact) · No record of why a ticket was routed
Pain points: slow first response, inconsistent categorisation between agents, misrouting, urgent cases not prioritised, no data for improvement.

B2. Proposed AI-enabled workflow – TriageAssist

1 INPUTComplaint text + channel, customer tier, prior contacts
→
2 DATA PREPMask PII (phone, email, card), normalise text
→
3 AI PROCESSINGClassify category, score urgency, compute confidence
→
4 AI OUTPUTCategory, urgency, team, SLA, evidence, draft reply
→
5 VALIDATION CHECKConfidence ≥ 55%? No safety / legal / fraud cue? Enough detail? English?
IF YESAuto-route recommendation
→
6 HUMAN REVIEWL1 agent accepts, overrides (with note) or rejects
→
7 DECISION / ACTIONTicket routed to team; personalised reply sent
→
8 RECORD / FEEDBACKDecision log (AI vs final) → monthly lexicon & threshold tuning
IF NOEscalate
→
ESCALATION PATHLow confidence / mixed issue / vague / non-English → Supervisor triage queue. Safety, legal, fraud, security → Escalations Supervisor within 4 working hours.
→
HUMANSupervisor decides & assigns manually
→
BACK TO 8Logged for feedback
